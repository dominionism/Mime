## Goal
Build Mime as a locally signed, privacy-preserving macOS menu-bar utility that recognizes deliberate hand gestures, runs configured actions, controls the primary-display pointer, and later learns user-recorded static poses.

## Constraints
- The user-facing product name is **Mime**.
- Target a **personal tool first** on the current Apple Silicon Mac; public distribution is not part of the first release.
- Deliver a standalone, locally signed `Mime.app` that runs outside Xcode.
- Use a **menu-bar utility** with a settings window and compact recognition-state feedback.
- Process camera data **on-device and ephemerally**: never persist or upload camera frames or hand landmarks.
- Recognize gestures from **either hand**.
- Require a **wake gesture followed by a command gesture**; avoiding false activations takes priority over minimum latency.
- Start with four assignable curated command poses: **fist, thumbs-up, V sign, and index-point**. The open-palm wake pose is reserved and cannot be assigned.
- The first usable milestone must launch applications, open URLs/files, run Apple Shortcuts, and run user-configured scripts or commands.
- First-milestone reliability: at least 9 of 10 deliberate wake-command sequences trigger correctly, no accidental command fires during 30 minutes of normal desk use, and action execution starts within 1 second after presenting the command pose.
- Add pointer control in the next milestone, limited to movement and deliberate left-click on the primary display; defer drag, scrolling, right-click, double-click, and multiple displays.
- Add user-recorded **static poses** as a later required milestone; dynamic motion gestures are out of scope.
- Each key work item is completed on its named branch, verified, opened as a PR into `master`, and merged before the next branch starts.
- Greenfield baseline: Xcode 26.6, Swift 6.3.3, Apple Silicon, and macOS 26.0. `/research` is still an unfilled scaffold; there are no source conventions, domain glossary entries, or ADRs to constrain the design.
- No valid code-signing identity is installed on the workstation. Use a stable bundle identifier/path and explicit ad hoc signing for the personal build; replacing the binary may require Camera and Accessibility permission to be granted again.

## Work items
1. **Create the native macOS application shell** — branch `feat/native-app-shell`
   - What: Create `Mime.xcodeproj` with a Swift 6 macOS application target and `MimeTests` unit-test target; set deployment to macOS 26.0, product name `Mime`, bundle identifier `com.dominionism.Mime`, and Apple Silicon architecture. Add `Mime/App/MimeApp.swift` using SwiftUI `MenuBarExtra`, `Mime/App/AppModel.swift` as the `@MainActor` composition root, `Mime/UI/MenuBarContentView.swift`, `Mime/UI/SettingsView.swift`, `Mime/Resources/Info.plist`, and `Mime/Mime.entitlements`. Set `LSUIElement` so Mime has no persistent Dock icon, include `NSCameraUsageDescription`, enable the camera entitlement and Hardened Runtime, and leave App Sandbox disabled because later milestones intentionally launch arbitrary local commands and post accessibility events. The menu must expose Start/Stop Recognition, Settings, current camera/accessibility status, and Quit. Configure manual ad hoc signing (`CODE_SIGN_IDENTITY = -`, no development team) and prove an archived `Mime.app` launches outside Xcode from `/Applications/Mime.app`.
   - Why: Establishes the executable, permission metadata, lifecycle, signing identity, and test seam required by every later capability.
   - Depends on: none.
   - Risk: Ad hoc signatures change when the binary changes and can invalidate macOS privacy grants; keep the bundle identifier and install path fixed, require reauthorization after replacement when macOS asks, and verify repeated relaunches of the same installed artifact retain permissions.
   - Check: run `xcodebuild -project Mime.xcodeproj -scheme Mime -destination 'platform=macOS' test`, then `xcodebuild -project Mime.xcodeproj -scheme Mime -configuration Release -archivePath build/Mime.xcarchive archive`; install the archived app, verify it with `codesign --verify --deep --strict /Applications/Mime.app`, launch it directly, and observe its menu-bar item and Settings window.
   - Source: inferred from the greenfield repository scan and the selected local-app/menu-bar constraints.

2. **Build the ephemeral camera-to-hand-pose pipeline** — branch `feat/hand-pose-pipeline`
   - What: Add `Mime/Permissions/CameraPermissionController.swift`, `Mime/Capture/CameraCaptureService.swift`, `Mime/Vision/HandPoseDetector.swift`, and `Mime/Domain/HandPoseSample.swift`. `CameraCaptureService` owns one `AVCaptureSession`, uses the default video camera, emits native pixel buffers from a dedicated serial queue, sets `alwaysDiscardsLateVideoFrames = true`, and avoids BGRA conversion. `HandPoseDetector` keeps at most one Vision request in flight, drops superseded frames, configures `VNDetectHumanHandPoseRequest.maximumHandCount = 1`, and emits an `AsyncStream<HandPoseSample>` with newest-only buffering. Each sample contains timestamp, chirality, recognized joint positions, and confidence—not an image. Add `Mime/UI/HandTrackingDiagnosticsView.swift` that draws only an abstract joint skeleton and confidence state so camera frames never enter persistence or logs. Start capture only while recognition or diagnostics are enabled and stop it when both are off.
   - Why: Provides bounded-latency hand landmarks without accumulating frames, wasting conversions, or violating the privacy boundary.
   - Depends on: item 1.
   - Risk: Vision work can lag the capture queue and increase memory or latency; verify late frames are discarded, the stream buffer never exceeds one sample, Start/Stop releases the camera indicator, and Instruments shows no growing frame backlog during a 10-minute run.
   - Check: unit-test permission/state transitions and newest-only delivery with fakes; on the target Mac, grant Camera access, start recognition, observe the abstract skeleton follow either hand, then stop and confirm camera use ends.
   - Source: researched from Apple’s [Vision hand-pose request](https://developer.apple.com/documentation/vision/vndetecthumanhandposerequest) and [AVCaptureVideoDataOutput](https://developer.apple.com/documentation/avfoundation/avcapturevideodataoutput) documentation.

3. **Recognize curated poses through a deliberate safety gate** — branch `feat/curated-gesture-gate`
   - What: Add `Mime/Gestures/HandPoseNormalizer.swift`, `Mime/Gestures/CuratedGestureClassifier.swift`, `Mime/Gestures/GestureGate.swift`, and `Mime/Domain/GestureID.swift`. Normalize landmarks around the wrist, divide coordinates by palm scale, rotate to a canonical wrist-to-middle-MCP axis, and mirror left-hand samples into right-hand space. Classify open palm, fist, thumbs-up, V sign, and index-point from joint angles and normalized fingertip distances; reject a pose when required joints are below 0.5 Vision confidence or the classifier score is below 0.85. Implement a clock-injected state machine: open palm stable for 600 ms enters `armed` for 3 seconds; one command pose stable for 400 ms emits one event; emission enters a 2-second cooldown and requires the pose to fall below 0.6 for 300 ms before another command. Low-confidence/missing-hand input resets stabilization. Add `Mime/UI/GestureStatusOverlay.swift`, a nonactivating compact HUD showing listening, wake progress, armed countdown, recognized pose, cooldown, and errors.
   - Why: Converts noisy landmarks into a small, explainable vocabulary while making accidental activation structurally difficult.
   - Depends on: item 2.
   - Risk: Mirrored hands or borderline finger shapes can collide; use synthetic landmark fixtures for both chiralities and ensure every fixture’s winning score exceeds the runner-up by at least 0.15. A failed margin emits no gesture.
   - Check: deterministic unit tests cover every state transition, timeout, confidence boundary, cooldown/release rule, all five poses, mirrored inputs, and ambiguous/no-hand inputs; manually perform 10 wake-command sequences per command pose from either hand.
   - Source: specified from geometry/state-machine knowledge, constrained by the user-selected wake-command model, either-hand support, gesture set, and false-activation priority.

4. **Persist mappings and execute all first-release action types** — branch `feat/gesture-action-bindings`
   - What: Add `Mime/Actions/ActionDefinition.swift` as a versioned `Codable` enum for `launchApplication`, `openURL`, `openFile`, `runShortcut`, and `runShellCommand`; add `GestureBinding`, `Configuration`, `ConfigurationStore`, `ActionExecutor`, and concrete executors under `Mime/Actions/` and `Mime/Persistence/`. Store configuration atomically at `~/Library/Application Support/Mime/configuration.json`; store application bundle identifiers with fallback URLs and file/folder security-scoped bookmarks, but never landmark or image data. Resolve and launch apps/files/URLs with `NSWorkspace`. Run Shortcuts as `/usr/bin/env` arguments `shortcuts`, `run`, and the unquoted shortcut name; capture standard error and treat documented termination status 0 as success and 1 as failure. Run configured commands explicitly through `/bin/zsh -lc`, display a security warning and require confirmation when saving or changing such a binding, capture output/error with a fixed in-memory size limit, and never interpolate gesture-derived values. Add settings editors/pickers for one binding per curated command pose plus result feedback in the HUD. Serialize action execution so one recognized event starts at most one process/action.
   - Why: Completes the first useful workflow: a deliberate gesture reliably performs a user-selected macOS action.
   - Depends on: item 3.
   - Risk: Invalid bookmarks, renamed apps/Shortcuts, hanging interactive Shortcuts, and unsafe shell text can fail or block; expose explicit success/failure, allow cancellation, impose a configurable 30-second process timeout default, and keep execution off the main actor. The shell editor must state that commands run with the user’s full privileges.
   - Check: unit-test configuration migrations/atomic replacement and executor result mapping with injected `NSWorkspace`/process fakes; manually bind and successfully execute one application, URL, file, noninteractive Shortcut, and harmless `printf` shell command. Then meet the selected bar: at least 9/10 wake-command sequences, zero accidental executions during 30 minutes of ordinary desk use, and execution start within 1 second of the command pose.
   - Researched: Apple documents `shortcuts run "Shortcut Name"` and exit status 0/1 in the current [Shortcuts User Guide](https://support.apple.com/guide/shortcuts-mac/run-shortcuts-from-the-command-line-apd455c82f02/mac); `NSWorkspace` is Apple’s API for [launching apps and opening URLs/files](https://developer.apple.com/documentation/appkit/nsworkspace).

5. **Add primary-display pointer movement and left-click** — branch `feat/hand-pointer-control`
   - What: Add `Mime/Permissions/AccessibilityPermissionController.swift`, `Mime/Pointer/PointerModeController.swift`, `Mime/Pointer/PointerMapper.swift`, and `Mime/Pointer/PointerEventPoster.swift`. Request Accessibility trust only when pointer control is first enabled and refuse to post events while untrusted. Reserve a 1.5-second continuous open-palm hold to enter pointer mode; require transition to index-point before movement begins; exit with a fist held for 1 second or the menu-bar Stop command. Map a calibrated central camera region (`x: 0.15...0.85`, `y: 0.15...0.85`) onto `NSScreen.main.frame`, mirror horizontal movement for camera-like control, invert/convert coordinates inside `PointerMapper`, clamp to the primary display, apply exponential smoothing with initial `alpha = 0.25`, and post at no more than 60 Hz. Detect a click when normalized thumb-tip/index-tip distance stays below 0.28 for 150 ms; require release above 0.40 before another click. Post only one left-button down/up pair through `CGEvent`. Show pointer mode, permission state, and click feedback in the HUD; expose sensitivity, active-region, and smoothing controls in Settings.
   - Why: Adds the requested hands-free pointing capability without expanding immediately into the full mouse gesture vocabulary.
   - Depends on: item 4.
   - Risk: Coordinate-space inversion, jitter, and pinch chatter can cause misplaced or duplicate clicks; unit-test every primary-screen corner and clamp, keep down/up paired in one API, and require pinch hysteresis/release. Provide an always-available menu Stop control as the fail-safe.
   - Check: unit-test coordinate mapping, smoothing, mode transitions, permission denial, and click hysteresis with a fake event poster; manually reach all four screen corners, hit a 44×44-point target at least 9/10 times, produce 10 single clicks without duplicates, and confirm no click posts after permission is revoked or pointer mode exits.
   - Source: researched from Apple’s [Accessibility trust API](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions) and [CGEvent posting API](https://developer.apple.com/documentation/coregraphics/cgevent/post(tap:)); scope comes from the selected primary-display, movement, and left-click constraints.

6. **Record and recognize custom static poses** — branch `feat/custom-static-gestures`
   - What: Generalize `GestureID` to distinguish reserved built-ins from UUID-backed custom poses; add `Mime/CustomGestures/CustomGestureTemplate.swift`, `CustomGestureRecorder.swift`, `CustomGestureMatcher.swift`, and a guided recorder in Settings. Entering record mode pauses action execution. Capture five stable normalized feature vectors for a named pose, compute the mean vector and per-feature variance, and store only those derived numbers. Reject recordings within the built-in/custom conflict threshold, then require three validation attempts with at least two successful matches and a best-vs-runner-up score margin of 0.20 before saving. Match custom templates with variance-weighted Euclidean distance after the same chirality normalization as curated poses; require threshold plus margin, otherwise emit no event. Permit each accepted custom pose to use the same action editor/executor as curated poses. Protect open palm and pointer-mode controls from being overridden.
   - Why: Delivers the required personal gesture vocabulary without collecting images or taking on dynamic time-series recognition.
   - Depends on: item 5.
   - Risk: Too few or inconsistent examples can overfit and create false activations; guided stability checks, conflict rejection, validation attempts, and nearest-runner margin make failure visible before a binding becomes active.
   - Check: deterministic tests cover averaging/variance, either-hand normalization, serialization, built-in conflicts, custom-to-custom conflicts, validation rejection, and ambiguous matching; record one custom pose, relaunch Mime, verify it persists, and meet the same 9/10 intentional and zero-in-30-minutes accidental-activation bar.
   - Source: specified from template-classification knowledge and the selected static-only, local/ephemeral privacy, and false-activation constraints.

## Out of Scope
- Dynamic recorded gestures such as waves, circles, or swipes.
- Two-hand combination gestures or simultaneous multi-hand tracking.
- Multiple-display pointer control.
- Drag, scroll, right-click, double-click, or text entry by gesture.
- Cloud processing, camera/landmark recording, telemetry, or accounts.
- App Store distribution, public Developer ID packaging/notarization, automatic updates, or launch-at-login.
- iPhone, iPad, Windows, or Intel Mac support for the personal first release.
